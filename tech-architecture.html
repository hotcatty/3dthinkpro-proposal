Maintenance · 运维说明

日常运营和维护代码，是两件完全不同的事

Shopify 后台负责一切电商运营，代码只负责网站视觉。这两个维度完全独立，互不干扰。

运营任务谁来负责需要改代码说明
上架新商品、修改价格 Shopify Admin 后台 不需要 Shopify 商品管理 UI 完全独立于前端代码
处理订单、安排发货 Shopify Admin 后台 不需要 订单、发货、退款全在 Shopify 后台操作
收款、支付管理 Shopify Payments / PayPal 不需要 Shopify 全权处理，PCI 合规，资金直接到账
运费规则、物流设置 Shopify Shipping 配置 不需要 在 Shopify 后台设置运费规则即可
用户评价 Judge.me Headless API 一次性接入 Judge.me 提供 REST API，调接口取数据，样式完全自定义，一次接入永久使用
邮件营销、弹窗 Klaviyo JS 脚本 不需要 一行脚本嵌入，与技术架构无关
网站视觉调整 Next.js 前端 + AI 需要，但极快 有 AI 辅助，改一个模块以分钟计，远快于在 Shopify 主题编辑器里手动操作

AI 开发效率 vs. 无代码平台

无代码（Shopify 主题编辑器）的本质是：有限的选项 → 点来点去 → 效果受限。做设计调整反而更费时间。

用代码 + AI 的路线，对一个懂设计审美的运营者来说，只需要自然语言描述需求，几分钟内生成、验证、落地。实际操作效率高于无代码方案，不是低于。

Checkout · 结算页方案

结算页跳转问题——三种解法

点击购买跳转到 Shopify 白色默认结算页，视觉断层大。这个问题是有解的。

关于 Stripe：它不是 Shopify 的功能，是一家独立的支付基础设施公司。

Stripe 是美国最大的支付处理公司，Amazon、Google、Spotify 都用它。有意思的是：Shopify Payments 本身就是架在 Stripe 上面的。Stripe 完全独立于 Shopify，可以在任何网页里直接嵌入使用。

费用：2.9% + $0.30 /笔，和 Shopify Payments 完全一样。没有月费，按实际成交计费。
核心价值：提供 React 组件库（Stripe Elements），可以把支付表单直接嵌入我们自己的页面，用户全程不跳转，结算页 100% 自主设计。

方案 1 · 最快

Shopify Checkout CSS 品牌化

所有 Shopify 套餐（含 Basic $39）均支持对 Checkout 页面做 CSS 覆盖：改黑色背景、替换 Logo、调整字体颜色。不改结构，但视觉断层可以大幅降低。

成本：$0 · 工时：1–2 小时

方案 2 · 推荐

Stripe Elements 嵌入式结算

将 Stripe 支付组件直接嵌入我们自己的 Next.js 页面内，完全无跳转。用户在我们的界面内完成支付。Shopify 仍负责商品目录和订单记录，Stripe 负责支付收款。

费率：2.9% + $0.30/笔（与 Shopify Payments 相同）· 工时：1–2 天（一次性开发）

方案 3 · 远期

Shopify Plus 完整定制

Shopify Plus（$2,000/月）开放 checkout.liquid，可完全重写结算页前端。适合年营业额达到一定规模后作为升级方案。

月费：$2,000 · 当前阶段性价比差

// Next.js 结算页 — Stripe Elements 嵌入（无跳转） import { Elements, PaymentElement, useStripe } from '@stripe/react-stripe-js'; // 第 1 步：我们的后端 API 创建 PaymentIntent const { clientSecret } = await fetch('/api/checkout', { method: 'POST', body: JSON.stringify({ cartItems, shippingAddress }) }).then(r => r.json()); // 第 2 步：支付组件直接嵌在我们的页面里，完全无跳转 return ( <Elements stripe={stripePromise} options={{ clientSecret }}> <PaymentElement /> {/* Stripe 的安全支付表单，外观由我们的 CSS 完全控制 */} <button onClick={handleSubmit}>确认支付</button> </Elements> ); // 第 3 步：支付成功后，把订单同步到 Shopify 后台（一次性开发） await fetch('https://your-store.myshopify.com/admin/api/orders.json', { method: 'POST', headers: { 'X-Shopify-Access-Token': TOKEN }, body: JSON.stringify({ order: { line_items, customer, shipping_address } }) });

如果只需要后端能力——有哪些选择？

我们对 Shopify 的核心需求只有三样：商品目录管理、订单管理、支付接入。基于这三点，以下是市场上主要的替代方案。

综合建议

当前阶段继续用 Shopify。它的国际信任度、支付成功率、全球物流集成是其他平台短时间难以赶上的。对欧美买家来说，Shopify Checkout 有很高的品牌背书。

如果希望降本或自主性更强，Medusa.js（完全开源）和 Swell（SaaS + 早期免费）是最值得认真评估的两个方向。

如果团队主要在国内运营，店匠（Shoplazza）是最务实的选择：价格低、中文客服、专为出海卖家设计。

Plugins · 插件兼容性

哪些插件用不了？我们真的需要它们吗？

插件的本质是"数据 + 样式的打包方案"。无头架构中，我们只取数据（API），样式自己做，效果往往更好。

插件类别代表产品无头兼容对我们的实际影响
商品评价 Judge.me、Yotpo API 可接 影响高，但可解。Judge.me 提供 Headless REST API，只取评价数据，样式自己实现，效果更贴合品牌调性
在线客服 Tidio、Gorgias 完全可用 JS 脚本嵌入，无架构限制
邮件营销 / 弹窗 Klaviyo、Mailchimp 完全可用 JS 脚本嵌入，无架构限制
商品配置器 Infinite Options 不可用 影响高，但自建更好。车型年份选择器已在原型中自建，交互比任何插件更精准，视觉完全符合品牌
SEO 工具 Smart SEO 原生优于插件 Next.js 可直接控制所有 meta 标签和结构化数据，SEO 能力反而更强
数据分析 / 广告追踪 GA4、Meta Pixel 完全可用 通过 Google Tag Manager 注入，无任何限制
核心洞察：大多数插件提供的"样式"在我们的设计标准面前都是需要覆盖的累赘。我们真正需要的只是数据。用 API 取数据、用自己的代码渲染样式，既能完全控制视觉，又不依赖任何第三方插件的更新周期。
