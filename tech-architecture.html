Technical Architecture · 技术决策

独立站技术架构方案

为什么选前后端分离，它怎么运作，成本如何，以及后端平台的选型调研计划。

方向确定：前后端分离 前端原型已上线 后端平台：待调研 结算方案：待落地

Why · 为什么选这条路

前后端分离，比无代码建站更适合我们

市面上主流的独立站建站方案有两种：无代码主题建站（Shopify 标准主题、SHOPLINE 等）和前后端分离。我们选择了后者。

对比维度无代码主题建站前后端分离（我们的方案）
设计自由度 受主题框架限制，改动靠拖拽选项，难以实现品牌级视觉 完全自由。每一处视觉细节由我们自己写，像 Motographe 那样的效果可以直接还原
修改效率 在主题编辑器里手动操作，选项有限，改半天效果不理想 AI 辅助，改一个模块以分钟计。需求用自然语言描述，快速生成、验证、上线
商业运营（商品/订单/支付） 平台后台操作，无代码 完全相同。商业后台仍由电商平台负责，日常运营无需写任何代码（详见下节）
月费成本 $29–$79/月 + 付费主题一次性费用 后端平台费用（待定）+ Vercel 免费托管，总体相当甚至更低
长期可维护性 依赖平台更新节奏，重大改版需重新购买主题或大量手动操作 代码在自己手里，随时可调整，AI 加持下维护成本持续降低
核心逻辑：前后端分离的本质是把"网站长什么样"和"商业系统怎么跑"拆开。视觉层完全自主，商业系统继续由成熟平台托底。两件事各归其位，互不妥协。

Operations · 日常运营

商业运营这块，和普通独立站没有任何区别

前后端分离只影响"网站视觉怎么做"。商品上架、订单处理、收款、物流——这些全在电商平台的后台完成，不涉及任何代码。

运营任务操作方式需要改代码
上架商品、调整价格 电商平台后台 → 商品管理 不需要
查看/处理订单 电商平台后台 → 订单 不需要
支付收款、退款 支付平台自动处理 不需要
运费规则设置 电商平台后台 → 运输配置 不需要
邮件营销 / 客服弹窗 Klaviyo / Tidio 脚本一次性接入 一次性，极简
网站视觉调整 前端代码 + AI 辅助修改 需要，但极快

Checkout · 结算方案

结算页三套方案

前后端分离在结算页有一个特殊问题：默认点击购买会跳转到 Shopify 原生 Checkout 页面，与我们的界面有视觉断层。以下是三个解决路径，由易到深。

方案 A · 短期

Shopify Checkout 品牌化

CSS 覆盖样式

所有套餐均支持，1–2 小时完成

为跳转后的 Checkout 页替换品牌配色、Logo、字体，跳转感大幅降低。不改结构，改的是外观。

方案 B · 中期推荐

Stripe 嵌入式支付

完全无跳转

2.9% + $0.30 /笔，无月费，一次性开发

将支付表单直接嵌入我们自己的页面，用户全程不离开。Shopify 继续管商品和订单，Stripe 管安全收款，前端样式 100% 由我们控制。

注：Stripe 是独立支付公司，Shopify Payments 底层即是 Stripe，费率完全相同。

方案 C · 远期

Shopify Plus

$2,000 /月

适合规模化后的升级方向

开放 Checkout 完整自定义权限，可彻底重写结算页前端。当前阶段性价比不足，作为远期方向保留。

后续调研项：Stripe 嵌入方案（方案 B）是兼顾体验和成本的最优路径，需进一步调研 Stripe 在目标市场（北美、欧洲）的合规要求，以及与 Shopify 订单系统的对接流程，作为下阶段落地任务。

Backend · 后端选型

后端平台待调研，尚未定论

我们对后端的核心需求只有三项：商品管理、订单管理、安全收款。以下平台值得进入下一步实测调研，再做最终决策。

重要：Shopify 的隐藏费用陷阱。如果我们用 Stripe 嵌入式支付（不走 Shopify Payments），Shopify 会在 Stripe 的 2.9%+$0.30 之外，额外再收 0.5%–2% 的交易手续费。也就是说，越想要设计自由，Shopify 就越贵。BigCommerce、Swell、Medusa.js 均无此问题。

调研计划 · 下一步行动

优先级 1：Shopify vs. BigCommerce。月费相同，但 BigCommerce 无额外交易手续费，无头 API 更好，SKU 上限更高。重点核实后台操作体验是否够顺手。

优先级 2：Swell 免费试用。注册账号试用后台，看 API 文档质量和 UI 流畅度，成本为零，值得快速验证。

国内平台的定位：若最终采用 Stripe 嵌入（用户完全看不到后端是什么平台），国内平台的信任度劣势消失，届时店匠的低月费优势更值得认真评估。

决策原则：价格差距不大时选最顺手的；若 BigCommerce 或 Swell 在 API 体验和综合费率上有明显优势，则切换是合理的。
